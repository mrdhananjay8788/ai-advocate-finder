# Database Documentation

This document describes the PostgreSQL database schema modeled via Prisma for Phase 1 of the Advocate Finder platform.

## Models

### 1. User
- **Purpose**: Core authentication and identity record for all users.
- **Fields**:
  - `id` (String): Primary key (UUID)
  - `email` (String): Unique identifier for login
  - `passwordHash` (String): Secure bcrypt password hash
  - `role` (Role enum): Determines the account type (`CLIENT`, `ADVOCATE`, `ADMIN`)
- **Relationships**:
  - 1-to-1 with `Client` (if role = CLIENT)
  - 1-to-1 with `Advocate` (if role = ADVOCATE)

### 2. Client
- **Purpose**: Stores profile details specifically for clients.
- **Fields**:
  - `id` (String): Primary key
  - `name` (String): Full name of the client
  - `city` (String?): Optional location details
- **Relationships**:
  - Belongs to `User`
  - 1-to-many with `Case` (A client can create multiple cases)
  - 1-to-many with `ChatSession` (A client can have multiple AI sessions)
  - 1-to-many with `ConnectionRequest` (Requests sent to advocates)

### 3. Advocate
- **Purpose**: Stores the professional profile of legal advocates.
- **Fields**:
  - `id` (String): Primary key
  - `name` (String): Full name of the advocate
  - `barRegNumber` (String): Unique Bar Registration ID
  - `verifiedStatus` (VerificationStatus enum): Admin approval state
  - `practiceAreas` (String[]): Areas of expertise
  - `courts` (String[]): Courts where they practice
  - `languages` (String[]): Spoken/Written languages
  - `availabilityStatus` (Boolean): Switch to indicate if taking cases
- **Relationships**:
  - Belongs to `User`
  - 1-to-many with `Match` (Cases they matched with)
  - 1-to-many with `ConnectionRequest` (Requests received from clients)

### 4. Case
- **Purpose**: Represents a legal problem submitted by a Client.
- **Fields**:
  - `id` (String): Primary key
  - `caseType` (CaseType enum): Standardized legal category
  - `jurisdiction` (String): City/region
  - `urgencyLevel` (UrgencyLevel enum): Priority metric
  - `rawTranscript` (String): The unstructured chat transcript from the AI
  - `structuredSummary` (String): LLM-generated JSON summary of facts
  - `status` (CaseStatus enum): Progress tracking (`OPEN`, `MATCHED`, `CLOSED`)
- **Relationships**:
  - Belongs to `Client`
  - 1-to-many with `Match` (Suggested advocates)
  - 1-to-many with `ConnectionRequest` (Active connection intents)

### 5. ChatSession & ChatMessage
- **Purpose**: Temporarily stores the conversational intake flow before it is extracted into a `Case`.
- **Fields**:
  - `ChatSession.status`: Active/Completed state.
  - `ChatMessage.role`: Role of the sender (`USER`, `ASSISTANT`, `SYSTEM`).
  - `ChatMessage.content`: The message text.
- **Relationships**:
  - A `ChatSession` belongs to a `Client`.
  - A `ChatMessage` belongs to a `ChatSession`.

### 6. Match
- **Purpose**: Read-only suggestions generated by the Matching Engine.
- **Fields**:
  - `id` (String): Primary key
  - `matchScore` (Float): Percentage representing suitability (0-100)
  - `status` (MatchStatus enum): Suggested, Accepted, Declined
  - `scoreBreakdown` (Json): Explanation of why this score was given.
- **Relationships**:
  - Belongs to a `Case`
  - Belongs to an `Advocate`

### 7. ConnectionRequest
- **Purpose**: The actionable request sent by a Client to an Advocate.
- **Fields**:
  - `id` (String): Primary key
  - `status` (ConnectionRequestStatus enum): Workflow state (`PENDING`, `ACCEPTED`, `DECLINED`)
  - `clientMessage` (String?): Initial note from client
  - `advocateResponse` (String?): Reply from advocate
- **Relationships**:
  - Belongs to `Client` (Sender)
  - Belongs to `Advocate` (Receiver)
  - Belongs to `Case` (Context)

## Enums
- **Role**: `CLIENT`, `ADVOCATE`, `ADMIN`
- **VerificationStatus**: `PENDING`, `VERIFIED`, `REJECTED`
- **ConnectionRequestStatus**: `PENDING`, `ACCEPTED`, `DECLINED`, `CANCELLED`
- **CaseStatus**: `OPEN`, `INTAKE_COMPLETED`, `MATCHED`, `CONNECTION_PENDING`, `CONNECTED`, `ONGOING`, `CLOSED`
